# 网安初阶实验场 · 学案

> 配套站点：HyaCy//LAB
> 适用对象：网络安全零基础学员
> 建议课时：1 课时（45 分钟）
> 环境要求：一台能打开浏览器的电脑

## 一、学习目标

完成本课后，你应当能够：

1. 根据长度和格式判断常见哈希的类型，解释为什么加盐能拖慢破解。
2. 说出 SQL 注入的成因，并写出对应的修复方式。
3. 用显示过滤器和“追踪 TCP 流”在流量里定位明文密码。
4. 按正确顺序走完一次漏洞利用流程，并说明模块和 Payload 为什么要匹配目标。
5. 从指纹扫描结果里找出带已知漏洞的组件。
6. 解释越权访问（IDOR）的成因，并指出校验应该放在哪一端。

## 二、实验须知

- 全部操作都在浏览器里模拟，不扫描、不连接任何真实目标。
- 不在页面里输入自己的真实账号、密码或其他信息。
- 每过一个实验，读一遍页面底部的“如何防护”。

## 三、课前预习：8 张概念卡（约 8 分钟）

先猜答案，再翻面。每张卡控制在一分钟左右。

| 卡片 | 问题 |
|------|------|
| 哈希 | 系统为什么不直接存你的密码？ |
| 加盐 | 两个人用同一个密码，存下来的哈希会一样吗？ |
| SQL 注入 | 输入框里的文字，什么时候会变成程序的一部分？ |
| 抓包分析 | 没加密的密码在网上传输时，是什么样子？ |
| 漏洞利用框架 | 一次漏洞利用要经过哪几步？ |
| 指纹与资产识别 | 动手之前，为什么要先弄清对方装了什么？ |
| 越权访问 | 改了网址里的一个编号，为什么能看别人的数据？ |
| 字典攻击 | 为什么“111111”几毫秒就会被破解？ |

## 四、实验（约 32 分钟）

### 实验 01 认出哈希的类型（T1110，约 4 分钟）

**任务**：给 5 条样本各选一个正确的类型。

**操作**：
1. 观察每条样本的长度和字符组成。
2. 对照右侧的“长度对照表”，在每行下拉框里选择类型。
3. 点“检查答案”。

**思考**：
- 两条样本都是 32 位十六进制时，只看长度还能不能确定算法？
- Base64 为什么不算哈希？

### 实验 02 跑一次字典破解（T1110，约 5 分钟）

**任务**：从 6 个候选口令里找出和目标摘要匹配的那个。

**操作**：
1. 点“开始比对”，观察每一行的变化。
2. 记下命中时是第几次比对。
3. 看“加盐之后”的对照表，比较 lin 和 mo 两行。
4. 回答第三步的选择题：哪种握手能离线跑字典？

**思考**：
- 为什么排在前面的口令先被撞到？
- 加盐为什么能让“预先算好全部哈希”的表格失效？

### 实验 03 SQL 注入：拼出来的登录（T1190，约 5 分钟）

**任务**：在不知道密码的情况下登录成功。

**操作**：
1. 在用户名框里随便输入，观察右侧 SQL 预览里橙色部分的变化。
2. 构造一段输入，让查询条件恒真。
3. 打开“启用参数化查询”开关，用同一段输入再登录一次。

**思考**：
- 参数化查询开启后，同一段输入为什么失效了？
- 除了登录框，还有哪些输入位置可能出现同样的问题？

### 实验 04 从流量里找出密码（T1040，约 5 分钟）

**任务**：从录好的 12 个数据包里找出一个明文密码。

**操作**：
1. 在显示过滤器里输入 `ftp`，看列表剩下哪些包。
2. 选中任意一个包，点“追踪 TCP 流”。
3. 找到以 `PASS` 开头的那一行，把密码填进答题框。

**思考**：
- 同一份流量里的 TLS 数据包为什么读不出内容？
- 把 FTP 换成什么协议可以避免这个问题？

### 实验 05 走通一次利用流程（T1190，约 6 分钟）

**任务**：按正确流程完成一次模拟利用。

**操作**：
1. 用上下箭头把六个步骤排成正确顺序，点“检查顺序”。
2. 阅读目标信息，选一个服务对得上的 exploit 模块。
3. 填写 RHOSTS 和 LHOST，点“检查参数”。
4. 选一个和目标系统匹配的 Payload。
5. 点“运行 exploit”，阅读终端输出。

**思考**：
- 选错模块时，提示里给出的理由是什么？
- RHOSTS 和 LHOST 各自指向哪台机器？

### 实验 06 扫描站点指纹（T1595，约 4 分钟）

**任务**：从扫描结果里找出需要优先处理的组件。

**操作**：
1. 勾选要枚举的对象，点“开始扫描”。
2. 阅读输出，注意版本号后面带“latest”的括号。
3. 在判定题里选出有漏洞的一项。
4. 选择处置方式。

**思考**：
- 只勾“用户名”时，第二步会发生什么？为什么？
- 有安全版本可用时，为什么优先升级而不是停用插件？

### 实验 07 别人的饭卡和订单（TA0008，约 3 分钟）

**任务**：两个剧情各完成一次越权访问，再打开防御开关对比结果。

**剧情 1**：A 校有一套 NFC 饭卡系统，刷卡就能在食堂消费，这张卡同时是校内身份凭据。
1. 在“最近刷卡记录”里点一条别人的记录。
2. 点“读卡”，看看读到了谁。
3. 点“消费”。
4. 打开“校验卡内密钥”，再读一次卡。

**剧情 2**：商城订单页只凭地址里的编号取数据。
1. 把地址栏里的编号改成别人的，点“前往”。
2. 打开“服务端校验属主”，再前往一次。

**思考**：
- 两个剧情里，系统都只核对了什么？
- 属主校验为什么必须放在服务端，放在前端行不行？

## 五、课堂小结（约 5 分钟）

对照右侧“知识笔记”里的 7 条结论，用自己的话回答：

1. 这 7 个实验里，哪几个问题的根源是“把用户输入当成了程序的一部分”？
2. 哪几个的根源是“只认编号，不核对身份”？
3. 每个实验对应的防护措施，能不能归并成两三类？

## 附：教师参考答案

### 概念卡要点

| 卡片 | 要点 |
|------|------|
| 哈希 | 单向，不可逆；系统只存摘要 |
| 加盐 | 密码相同、盐不同，摘要就不同 |
| SQL 注入 | 输入被直接拼进语句，就获得了改变语句的能力 |
| 抓包分析 | 明文协议的账号密码原样出现在数据包里 |
| 漏洞利用框架 | 信息收集、找模块、加载、配参数、选 Payload、运行 |
| 指纹与资产识别 | 版本号决定有哪些已知漏洞可用 |
| 越权访问 | 只认 ID、不核对身份 |
| 字典攻击 | 越常见的口令排得越靠前 |

### 思考题参考要点

**实验 01**
- 不能。MD5、NTLM 等算法的输出都是 32 位十六进制，需要结合来源、字符集或专用工具判断。
- Base64 是编码，可以原样还原，没有“单向”这个性质。

**实验 02**
- 字典按常见程度排序，越常见的口令越早被比对。
- 每个用户有自己的盐，攻击者没法提前为所有口令算好一张通用的表，只能针对每个盐分别计算。

**实验 03**
- 输入只作为参数传入，不会进入 SQL 语句本身，`' OR 1=1--` 被当成一个普通字符串。
- 搜索框、URL 参数、请求头、Cookie 等，所有进入查询的位置都要用参数化。

**实验 04**
- 内容经过 TLS 加密，抓到的只是密文。
- FTPS、SFTP，或者直接用 HTTPS 传输。

**实验 05**
- 目标没有开放对应的服务，或者模块只做探测、需要已有凭据、系统不符。
- RHOSTS 是目标地址，LHOST 是攻击机自己的地址，用于接收回连。

**实验 06**
- 第二步没有可判定的组件。没枚举到的组件无从判断有无漏洞。
- 升级直接去掉了漏洞，功能保留，改动最小。停用会牺牲功能。

**实验 07**
- 剧情 1 只核对卡号，剧情 2 只核对订单编号。
- 不行。前端校验可以被绕过，请求可以伪造，服务端必须自己确认当前用户有没有权访问这条数据。
